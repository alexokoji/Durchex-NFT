# Durchex contracts

`DurchexNFT.sol` (ERC-721 with EIP-712 lazy-mint voucher redemption + EIP-2981
royalties) and `DurchexMarketplace.sol` (fixed-price sales, resales, English
auction settlement, platform fee + royalty splitting). Full design in
[`../docs/Durchex-NFT-Marketplace-Full-Specification.pdf`](../docs/Durchex-NFT-Marketplace-Full-Specification.pdf)
section 5.

This is a separate Hardhat project (own `package.json`/`node_modules`) so its
toolchain (ethers, Hardhat) doesn't collide with the Next.js app's (wagmi,
viem) — the app never imports from here directly, it just needs the deployed
addresses (`deployments.json`, generated by `deploy.ts`) and the voucher shape
already implemented client-side in `../lib/web3/voucher.ts`, which mirrors
`NFTVoucher` in `DurchexNFT.sol` exactly.

```bash
npm install
npm run compile
npm run test        # 11 tests: voucher redemption, replay protection,
                     # access control, fee/royalty math
```

## Deploying

```bash
# .env (or export directly): AMOY_RPC_URL, DEPLOYER_PRIVATE_KEY, optionally FEE_RECIPIENT_ADDRESS
npx hardhat run scripts/deploy.ts --network amoy
```

This deploys both contracts, wires `DurchexNFT.setMarketplace(...)`, and
writes the addresses to `deployments.json` (keyed by network name) — that
file is what `lib/web3/config.ts` in the app would read once contracts are
live, so a collection's `contractAddress` stops being empty and the item
detail page's Buy Now / Place Bid buttons can call the real contracts instead
of showing the "not wired up yet" notice.

`npx hardhat run scripts/deploy.ts --network hardhat` deploys to a disposable
in-memory chain — good for a sanity check, but the addresses aren't real and
shouldn't be recorded in `deployments.json`.
